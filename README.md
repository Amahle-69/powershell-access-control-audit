
# PowerShell Access Control Audit

## Project Overview

This project demonstrates how PowerShell can compare recorded employee group memberships against an approved access matrix and identify discrepancies for review.

The scenario uses the fictional company Mahlangu Business Solutions, with employees in Finance, Human Resources, IT, and Operations.

The initial implementation runs locally using fictional CSV data. It does not connect to Active Directory and does not grant or remove permissions.

## Business Problem

Employee responsibilities and access requirements can change over time. Recorded group memberships may not always match an organisation's approved access rules.

This project helps an IT Support or security team identify:

- Required group memberships that appear to be missing.
- Recorded group memberships that are not listed as approved for the employee's department.
- Employee records that cannot be reliably audited because of missing or inconsistent data.
- Duplicate membership rows that may indicate problems in the source export.

These are discrepancies for investigation, not automatic proof of unauthorised access.

## Features

- Imports employee records with `Import-Csv`.
- Imports an approved department-to-group access matrix.
- Imports recorded employee group memberships.
- Validates required CSV headers and important fields.
- Detects duplicate employee IDs.
- Detects missing required groups.
- Flags unexpected group memberships.
- Detects duplicate membership rows.
- Generates recommendations for authorised review.
- Exports the audit results to CSV.
- Includes automated tests for expected access findings and invalid input.
- Does not change account permissions or group memberships.

## How to Run the Audit

Open PowerShell in the project root directory.

### 1. Run the access-control audit

```powershell
.\scripts\Compare-AccessAssignments.ps1
```

The script reads the three CSV inputs, compares the recorded memberships with the access matrix, displays a summary, and generates:

`reports/access-control-audit.csv`

### 2. Run the main audit tests

```powershell
.\tests\Test-AccessControlAudit.ps1
```

This suite checks expected findings for the five fictional employees, missing group memberships, unexpected memberships, aggregate results, and recommendations.

### 3. Run the edge-case tests

```powershell
.\tests\Test-AccessControlEdgeCases.ps1
```

This suite tests missing employee CSV headers, duplicate employee IDs, blank membership fields, and duplicate employee/group records.

The edge-case suite creates temporary files and removes its temporary directory after testing.

## Demonstration Scenario

The sample data contains five fictional employees, five approved access rules, and eight recorded group-membership rows.

The audit identifies:

- Lerato Mthembu: `IT-Administrators` is unexpected under the sample Finance access matrix.
- Thabo Ndlovu: the required `HR-Users` group is missing, and no membership records were supplied.
- Zanele Dlamini: `Sales-SharedDrive` is unexpected under the sample IT access matrix.
- Naledi Mokoena: no discrepancy under the configured rules.

These results illustrate how an access review can identify discrepancies for further investigation.

## Safety and Limitations

- All employee names and group names are fictional.
- The email addresses use placeholder domains.
- The access matrix is a simplified demonstration, not an actual company policy.
- Unexpected group membership is a discrepancy to investigate, not proof of malicious or unauthorised access.
- Approved business exceptions may exist outside the sample matrix.
- Results depend on the accuracy and completeness of the supplied CSV data.
- The current implementation does not query a live Active Directory environment.
- The script does not grant, revoke, or otherwise modify permissions.

## Future Improvements
